# 抽象层级与颗粒度

## 五种不同的“分层”

这些结构可能交叉，但不能直接混为一棵树。

| 分层类型 | 典型关系 | 举例 |
| --- | --- | --- |
| 组成层级 | 部分—整体 | Agent 属于团队，团队属于系统 |
| 类型层级 | 类别—子类—实例 | 可视化技术 → 关系图引擎 → G6 |
| 认知抽象层级 | 原理—机制—细节 | 多视角表达 → 结构投影 → 节点筛选规则 |
| 执行粒度 | 任务—步骤—事件 | 用户任务 → Agent 决策 → 工具调用 |
| 观察尺度 | 全局—局部—微观 | 整体生态 → 某类技术 → 某个具体项目 |

一个多智能体系统里，下面几件事可以同时成立：

- Agent A 在组织上属于研发团队。
- Agent A 在某次任务中扮演审核者。
- Agent A 的一次执行又包含若干模型和工具调用。
- 从另一个观察视角看，Agent A 还可以被当成一个复杂子系统。

所以“一个对象处于哪个层级”不能只由对象本身的大小决定，还要考虑关系类型、观察目的和具体上下文。一个“个体”也不一定是不可继续分解的最小单元。

## 抽象时的两类操作

**表达压缩**：把许多低层节点合并显示为一个高层节点，但原始节点和关系依然存在，可随时展开。

**语义概括**：根据大量低层事实形成一个新的高层判断或理论。这个新判断必须有自己的解释、适用范围和论证依据。

两种操作不能混淆。例如一个部门有 20 个 Agent，与外部部门产生 60 条消息连接。折叠为“研发部门”时，可以显示一个部门节点和聚合边，但要保留原始连接的数量、方向、类型和来源。而概括为“研发部门是整个组织的信息交换中心”，已经是一项分析判断，需要新的评价依据，不只是把 60 条边合并。

好的系统应当允许从高层表达到原始结构做双向追溯。对分层认知文章同样成立：高层理论可以统摄大量细节，但不能因此删除它们原有的独立意义。
