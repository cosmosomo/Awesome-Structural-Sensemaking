# 板块 3 综合项目可视化案例

回答的问题：**一个真实的大型产品或系统，内部用了哪些可视化，做得怎么样。**

研究主体是"一个完整的系统或产品，以及它内部的所有可视化"，不是某个领域的某种可视化方案（那是板块 2）。例如一个多智能体管理项目，内部可能同时有工作流编辑器、运行 Trace、成本面板等多种可视化。以项目为单位，逐项记录并评估，评估表回指板块 1 和板块 2。

> 本板块与 [板块 2 的 c](../02-visualization-stack/c-applications/)（成熟应用中的交互）的对象重叠，分工待定。

## 评估表模板

每个项目一张表，一行一个可视化：

| 可视化项 | 对应的数据与层级（板块 2 b） | 结构类型与形式（板块 1） | 交互 | 评价 | 依据 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |

评价先用简短文字。是否引入评分维度，等收集几个项目之后再定。

"依据"写明评价来自什么：实际使用、官方 Demo、截图，还是只读了文档。

## 示例：多智能体管理平台的观察项（参考稿，待确认）

| 观察项 | 观察内容 |
| --- | --- |
| 整体架构 | 是否有全局架构视图？ |
| 协作关系 | 能否展示智能体之间的通信与任务交接？ |
| 流程编排 | 是否支持节点式流程编辑与执行展示？ |
| Trace | 是否支持调用树、时间轴、嵌套事件分析？ |
| 抽象层级 | 能否展开、折叠、聚合、钻取？ |
| 视角联动 | 架构、协作、任务、Trace 等视角能否互相映射？ |
| 交互质量 | 是否支持筛选、搜索、高亮、回放？ |
| 实现方式 | 使用哪些图形技术、数据模型和组件？ |
| 不足与机会 | 哪些重要的信息和关系没有得到表达？ |
