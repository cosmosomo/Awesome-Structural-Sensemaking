# 板块 3 综合项目索引与横向评测

第二板块负责分类、介绍技术和方案；这一板块负责对真实项目做横向比较，回答：什么项目在什么方面做得好？哪些能力经过验证？哪些没有覆盖？对研究有什么启发？

不要简单复制第二板块的项目列表。

| 文件 | 内容 |
| --- | --- |
| [`first-round-positioning.md`](first-round-positioning.md) | 第一轮代表项目的定位（报告级别，不是实测）。 |
| [`reproducible-tests.md`](reproducible-tests.md) | 五个可复现的测试场景。 |
| [`capability-matrix.md`](capability-matrix.md) | 能力矩阵与单项目评估表模板，待实测后填写。 |

## 评价拆成五个独立方面

| 评价方面 | 具体指标 |
| --- | --- |
| 结构表达 | 语义准确性、关系类型、层级保留、多维结构覆盖 |
| 视觉能力 | 图形类型、布局质量、密集网络可读性、空间利用 |
| 交互能力 | 展开折叠、关系聚合、筛选、钻取、多视图联动、时间探索 |
| 分析能力 | 依赖诊断、路径分析、异常发现、结构比较、影响分析 |
| 工程与产品 | 性能、易用性、集成难度、可扩展性、维护状态、许可证 |

分别评价，不算“可视化能力总分”。一个专门展示 Trace 的项目可能完全没有架构图，但这不意味着它设计得差；一个图渲染库没有完整的 Agent 业务模型，也不应因此被扣分。

## 证据级别

官方文档声称支持、项目代码能验证、公开 Demo 可以体验、我们亲自完成实测，是四种不同的证据。`catalog/evaluation-records.yaml` 里每条记录都标明 `evidence`：

| 取值 | 含义 |
| --- | --- |
| `report` | 调研报告依据官方文档做的归纳，本库未复核 |
| `docs` | 本库核对过官方文档 |
| `code` | 本库核对过源码 |
| `demo` | 本库体验过公开 Demo |
| `hands-on` | 本库亲自安装并实测 |

## 使用边界

收录条目至少区分：源码开源、含附加条件的许可证、源码可见但有使用限制、商业产品、研究原型、已归档。这些记录在条目的 `access`、`status`、`notes` 字段里，在 [`catalog/INDEX.md`](../catalog/INDEX.md) 的“备注”列直接可见。
