# 可复现的测试场景

为不同能力设计可复现的测试。这五种测试分别针对不同能力，不要求每个项目全部通过。目前都还没有执行。

每个测试里，被表达对象的**结构复杂度**由测试材料设定，**理解难度**由观察结果体现。两者的区分见[评价理论](../01-theory/evaluation-theory.md)。比较不同项目时，必须用同一份测试材料。

## 测试一：复杂图的聚合与展开

准备一个具有以下特点的测试系统：

- 100 至 500 个节点。
- 3 至 5 层父子嵌套。
- 多种不同含义的连接关系。
- 大量跨子系统连接。
- 至少存在循环依赖与高连接度节点。

观察：折叠后的聚合边是否保留重要语义；展开后能否恢复原有结构；节点位置是否剧烈跳动；用户是否能持续跟踪一个对象。

| 设定的结构复杂度 | 观察的理解难度 |
| --- | --- |
| 规模、嵌套深度、关系种类、跨边界连接、环与枢纽 | 聚合后语义是否保留，展开能否恢复，能否持续跟踪同一对象 |

## 测试二：多视图之间的对象一致性

同一批对象分别用组织架构图、网络图、流程图和时间图展示。

观察：一个对象是否有稳定身份；筛选或高亮状态是否可以跨视图保留；能否从一个视图进入另一个视图并准确定位到对应对象。

| 设定的结构复杂度 | 观察的理解难度 |
| --- | --- |
| 同一批对象具有组织、网络、流程、时间四种结构 | 对象身份、状态保留、跨视图定位 |

## 测试三：Agent 协作与实际 Trace

准备一个包含约 20 个 Agent、多个团队、并行任务、动态交接与工具调用的案例，同时构造：

- 静态角色和协作关系。
- 某次任务的实际执行路径。
- 多级决策与调用链。
- 有时间戳的运行事件。

评价系统能否把静态组织、任务路由、动态执行、微观调用连接起来。

| 设定的结构复杂度 | 观察的理解难度 |
| --- | --- |
| 多团队、并行、动态交接，静态结构与运行事件并存 | 能否在静态组织、任务路由、动态执行、微观调用之间连通 |

## 测试四：技术市场与产品市场的耦合地图

准备若干技术类别、具体技术、开源项目、产品、需求场景和技术依赖。

测试：能否只显示一个产品的技术基础；能否反查某项技术服务了哪些产品；能否切换分类层级；能否发现没有明确产品映射的技术区域。

| 设定的结构复杂度 | 观察的理解难度 |
| --- | --- |
| 多类实体和多种跨类别依赖 | 正查、反查、切换层级、发现空白区域是否容易 |

## 测试五：认知结构的完整性

给定一份包含许多论点、细节、例证和相互矛盾观点的复杂材料，要求系统生成分层结构。

检验：能否回溯到原始判断；能否区别不同类型的概念关系；新内容加入后是否造成重要知识丢失。

| 设定的结构复杂度 | 观察的理解难度 |
| --- | --- |
| 大量论点、细节、例证，含相互矛盾的观点 | 回溯原始判断、区分关系类型、吸收新内容时不丢失知识 |
